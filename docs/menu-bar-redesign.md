# 菜单栏下一版设计

状态：2026-10-04 设计预览，尚未替换当前菜单栏实现。

参考用户指定的 [CodexBar](https://github.com/steipete/CodexBar) 原生菜单观感：轻薄材质、细分隔线、紧凑文字和额度条。主窗口已经敲定，本次设计范围是 macOS 菜单栏。

## 布局

- 顶部保留应用名称和显示设置入口，取消逐个账号的顶部标签。
- 总览同时显示 5 小时、周两条聚合额度，每条附可用账号数。
- 全部账号直接列出 Gemini、Claude/GPT 的剩余额度，行末提供切换按钮；当前账号使用静态、小圆角标记。
- 账号区的周期选择只改变行内额度；总览始终保留两个周期。
- 今日 Token 与请求数属于本机记录，不冒充账号配额，也不归入聚合额度。
- 推荐逐行总览方案，保留邮箱以识别账号；备选矩阵方案用列对齐额度，点击账号查看身份详情。

## 用户已确认的聚合设置

在设置中允许选择 Gemini 系列、非 Gemini 系列、全部系列。选择影响总览统计范围；账号列表继续展示两类额度。

当前接口没有各档位的绝对 Token 上限，聚合条明确标为“平均剩余”，不能表示可相加的 Token 总量。

- 一个账号的一个共享池、一个周期只取一条观测，多个模型共用池时不能重复计算。
- 所选范围内，使用有效账号的共享池剩余比例做等权平均；“全部”包含 Gemini 与 Claude/GPT 两池。不同档位、不同池的平均只表示相对剩余状态。
- 禁用、禁止访问、验证阻塞、数据过期、重置边界已过、额度未知，不计入有效平均；显示有效统计覆盖和排除原因。
- 已知的低额度或零额度仍应纳入平均，不能为了抬高平均而剔除。
- 可用账号数按所选范围内各池均有有效数据且高于现有换号阈值判断；“全部”要求两池均满足。分母为全部已保存账号。
- 缺少所选周期时显示未知，不能借用另一个周期；没有有效观测时显示“—”，不能显示 0%。

## 原生材质落地要求

当前后端已经通过 `Effect::Popover` 设置材质，但前端 `MenuBarDashboard.css` 的白色 `rgba(255,255,255,0.78)` 铺底会削弱通透感。

落地时调整 WebView 的覆盖层，让 macOS 材质承担窗口背景；评估 macOS 26 的原生玻璃接口，旧系统保留原生模糊回退。预览中的背景只是材质示意，不能代替原生窗口验收。

需要在浅色、深色、不同桌面背景和“减少透明度”设置下验证文字可读性、圆角、阴影、退出焦点与关闭行为。

## 接入约束

继续使用已有账号切换协调与错误处理。当前账号以真实 App 身份同步结果为准，不能在识别失败时默认第一条保存账号。菜单栏读取展示所需数据，不把账号凭据带入视图。

设计预览的按钮只改变本地示例状态，不执行真实换号。
