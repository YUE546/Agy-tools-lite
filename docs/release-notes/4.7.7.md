## Acceptance status and experimental features

- Linux native Tauri/WebKitGTK acceptance passed for the integrated application code at `6896ce61ea25ac402a12db0098e631b0fe45462d`: synthetic account data, real IPC, light/dark themes and narrow-window layouts. This was a CI debug build and does not prove installed-package behavior, real account switching or tray-window behavior.
- Windows native GUI acceptance is **blocked**, with no native screenshots or successful GUI checks. The CI runner's WebView2 environment could not support that test. Windows release CLI and packaging checks passed separately; they are not a GUI acceptance result.
- macOS arm64 packaging and CLI checks passed. Final native window, menu-bar focus/transparency, Dock and login-item behavior still need acceptance on a Mac. Cross-platform GUI acceptance is not complete.
- Low-quota coordination and desktop login/background/Dock options are off by default. Native desktop integration remains experimental pending platform acceptance. Coordinated switching waits until all detected APP, IDE and `agy` clients have exited; it does not stop tasks, close/restart clients or migrate running work. Manual switching can close and restart Antigravity, so save work and verify the account afterward.

Linux screenshots and Chromium menu-layout previews use synthetic data. The menu previews are not native macOS screenshots. Build and CLI success must not be interpreted as complete native acceptance or a tested Homebrew installation.
