## Changes

- In-app download and installation of signed update packages, with progress, concurrent-update protection and explicit failures.
- Settings display the running application's version independently of the available release version.
- The homepage removes the duplicate cost-details popup. The model section is named **Model breakdown**, with **Token usage** and **Estimated cost** views. Its chart uses a softer palette.

## Validation and limits

Local validation: frontend build, 28 bilingual browser UI checks, 127 passing Rust library tests (2 platform-specific tests ignored), release-package validation tests and a real Tauri signature verification probe, including rejection of changed bytes. Platform CI supplies additional package build and native acceptance results; local browser tests are not physical Windows or Linux installation tests.

Update signatures are verified independently of operating-system code signing. The project still has no Apple Developer ID/notarization or Windows Authenticode certificate. On macOS, the new updater checks Gatekeeper before replacing the app; an untrusted release is rejected and the current application is preserved. Fully unattended Mac installation is therefore not claimed. Windows security prompts and Linux package-install authentication may still appear.

Versions with the previous notification-only updater need a one-time manual upgrade to acquire in-app downloading. Homebrew users can continue using `brew upgrade --cask antigravity-tools-lite`.

See [update behavior and trust boundaries](../software-updates.md).
