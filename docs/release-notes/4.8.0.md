# v4.8.0 — Windows and Linux delivery

- Windows now includes a dedicated console `agy-switch.exe`. PowerShell can invoke it directly, wait normally and receive the exit code; the desktop program keeps its GUI subsystem.
- All three platforms share terminal navigation and masked credential entry. Windows/Linux receive separate console downloads in addition to the desktop packages; the Linux deb also installs `/usr/bin/agy-switch`.
- The Windows/Linux tray dashboard follows the Mac dashboard’s three sections, with opaque surfaces, consistent identity/action alignment, neutral percentage text, yellow reset labels, and prewarmed window reuse. Preferences remain in Settings.
- Windows packaging builds the console executable before assembling the installer, which offers English/Simplified Chinese and current-user installation. The release includes checksums and source provenance for all five payloads.
- English and Chinese READMEs are reorganized around installation and desktop/terminal workflows, with separate Windows and Linux guides. Router dependencies include the current compatible security patches.

## Acceptance and limits

Local Mac regression checks passed 126 backend tests (two isolated helper cases ignored), 27 browser UI cases, 14 actual CLI read checks and 12 real PTY checks. Windows/Linux native window, terminal and package acceptance for the release source is pending final PR CI; do not tag or publish until the recorded results are reviewed and this paragraph is finalized.

Linux console commands do not initialize a display, but the binary still requires GTK3/WebKitGTK runtime libraries. APP switching requires an installed Antigravity client and its credential backend; no file-only CLI switch or background CLI daemon is provided. Desktop smart switching remains optional and does not guarantee every running task has completed or migrate tasks.

Native WebDriver acceptance uses synthetic accounts and an opt-in debug test feature. The Windows test passes only a driver port through the supported WebView2 API on elevated hosts; production builds cannot enable that path. Native viewport tests do not establish tray placement on every monitor, Wayland/KDE behavior, login startup, real authorization or authenticated switching on every OS.

Mac packages remain ad-hoc signed without Developer ID/notarization; Windows packages remain unsigned. The prior Brew installation/upgrade worked, but quarantined Mac launch failed platform-trust checks. No OS security settings or quarantine checks are removed by this release.
